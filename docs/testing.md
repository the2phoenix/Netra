# NETRA: Testing Strategy and Test Plan

Version 1.0 | 2026-10-31
Skills applied: Test Master (overall strategy: unit, integration, end to end, performance, security), Playwright Expert (browser flows), Chaos Engineer (failure drills), Code Reviewer, Security Reviewer.
Related: `features.md` (acceptance criteria), `trd.md` (formulas and thresholds), `software_engineering.md` (definition of done).

---

## 1. Goals and risk-based approach

With 48 hours, test where failure is **likely and expensive**, not everywhere.

| Risk | Why it matters | Where it is tested |
|---|---|---|
| Wrong maths (geo, SGP4 units, dead reckoning) | Silent and embarrassing in a viva | Unit tests with known answers (section 4) |
| Upstream failure and rate limits | Most likely cause of a live-demo failure | Integration and chaos tests (sections 5 and 8) |
| Frame rate collapse | Ruins the "wow" | Performance tests on the demo laptop (section 7) |
| Gesture false triggers | Makes the globe fly around by itself | Classifier and state machine tests on synthetic landmarks (section 4) |
| Lying UI (live label on stale data) | Honesty is a product requirement | E2E checks on badges and banners (section 6) |
| Secrets or owner data leaking | Security and ethics | Security tests (section 9) |

## 2. Test pyramid for this project

| Level | Tools | Count (target) | Runs |
|---|---|---|---|
| Unit (pure logic) | pytest; Vitest | about 50 | Every save, in seconds |
| Integration (API with fake upstreams) | pytest-asyncio, respx | about 20 | Every commit |
| End to end (browser, fixtures) | Playwright | about 12 | Before each milestone tag |
| Performance | Playwright (headed) reading `window.__netra.stats()` | 4 | On the demo laptop only |
| Chaos and failure drills | Manual plus Playwright network control | 8 | Sunday evening and Monday |
| Manual demo checklist | Human | 1 list | T-24 h, T-2 h, T-15 min |

**Coverage targets:** `geo/`, `input/gestures/` and `api/app/cache.py` at 90% line coverage. `api/` overall 80%. UI code has no coverage target; it is covered by E2E flows.

**Test-first for pure logic** (haversine, polygon, dead reckoning, footprint, classifier, cache): write the failing test from the table, then the code. This matches the `--tdd` mode in `gsd.md`.

## 3. Test data and fixtures

- `api/fixtures/` holds recorded JSON from the real feeds: satellites per group, 15 minutes of aircraft snapshots, quakes, fires. Recorded Sunday afternoon by `make fixtures`.
- `api/tests/data/` holds **small hand-made fixtures** for deterministic tests: three aircraft (one squawking 7700, one on the ground, one with no position), five satellites including a decayed one, two quakes.
- `web/tests/landmarks/` holds **synthetic hand landmark sets** (21 points) generated by a helper: open palm, fist, pinch, thumbs up, and noisy versions with Gaussian jitter. No webcam needed.
- Time is injected, never read from the system clock inside logic, so tests are repeatable.

## 7. Performance tests (demo laptop, headed browser, plugged in)

Run with the real GPU. Read `window.__netra.stats()` every second for 60 s.

| ID | Scenario | Pass criterion | Req |
|---|---|---|---|
| T-PERF-01 | Orbit view, 2,400 satellites, 1,800 aircraft, 300 quakes, normal mode | Median FPS 30 or higher, 1% low above 20 | NFR-01 |
| T-PERF-02 | Same, with night-vision mode and projector mode on | Median FPS drops by no more than 5 | VIS-01 |
| T-PERF-03 | Same, with gestures on (webcam running) | Median FPS 30 or higher, gesture pipeline 25 Hz or higher | GES |
| T-PERF-04 | Memory over 10 minutes | Heap growth under 50 MB (no leak in the per-frame loop) | NFR-01 |

Also record: worker time per SGP4 batch (target under 8 ms), main-thread long tasks (none over 50 ms), API latency (cached under 50 ms). If a test fails, apply the performance-mode caps from `trd.md` section 9 and re-test before cutting features.

## 11. Quality gates

| Gate | Must pass |
|---|---|
| Commit | Lint clean, fast unit tests pass |
| Phase complete | Unit and integration green, relevant E2E green, success criteria in `gsd.md` met, security checklist items for that phase |
| Milestone tag | All of the above plus the demo script runs end to end |
| Feature freeze (Sunday 23:00) | Full pyramid green, performance and chaos drills pass or have written exceptions, no open P0 or P1 bugs |

**Bug severity**
- **P0:** crash, freeze, data shown as live when it is not, secret leak. Stop everything.
- **P1:** wrong data, a Must feature failing, FPS below 20 at target load.
- **P2:** visual glitch, Should feature failing, slow animation.
- **P3:** polish.
